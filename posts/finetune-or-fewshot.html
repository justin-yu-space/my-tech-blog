为了抽工艺参数我差点微调 7B：8 个 few-shot 样本把完整率从 71% 拉到 92%

NPI 系统里有个功能：读工艺卡文本，抽出工序、关键参数和风险点，存进结构化字段。上线后字段完整率一直在 71% 左右徘徊——十份工艺卡有三份会漏掉关键参数。我盯着那些漏抽的样本看了半天，得出一个很专业的结论：通用模型不懂我们的工艺黑话，得微调。我甚至已经列好了 200 条标注计划、准备租 GPU。幸好动手前先做了一次对照实验，最后没微调，用 8 个样例把完整率提到了 92%。这两天的「差点踩坑」值得记下来。

我先算了一笔账

微调的账不能只算 GPU 钱。标注 200 条工艺卡，每条人工读加填字段约 3 分钟，是 10 小时；LoRA 微调一个 7B 模型，单卡 A10 跑 3 个 epoch 约 2 小时，机器成本约 ¥12；上线后还要维护模型版本、做评测回归、处理领域漂移。真正贵的是标注和长期维护，不是训练。而我们要解决的问题只是漏字段——这是指令遵循问题，不是知识缺失问题。这两个问题的解法根本不一样。

对照实验：四组，结果出乎意料

我拿 50 份有人工标注的工艺卡做评测，四组跑同一批数据：① 裸 prompt（「抽出工序、参数、风险」）字段完整率 71%；② 加 JSON Schema 约束到 80%；③ 加 8 个 few-shot 样例到 92%；④ LoRA 微调 7B 到 94%。第三组和第四组只差 2 个百分点，但第三组花了我 40 分钟挑样例，第四组花了 10 小时标注。

# few-shot 样例库：按零件类型分组，检索时动态挑选
FEWSHOTS = {
    "钣金": [
        {"input": "...", "output": {"process": "...", "key_params": [], "risks": []}},
        # ... 共 3 个
    ],
    "注塑": [ ... ],
    "机加": [ ... ],
}

def build_messages(part_type, card_text):
    shots = FEWSHOTS[part_type][:3]       # 同类 3 个即可，多了反而稀释
    msgs = [{"role": "system", "content": SYSTEM + SCHEMA_HINT}]
    for s in shots:
        msgs += [{"role": "user", "content": s["input"]},
                 {"role": "assistant", "content": json.dumps(s["output"], ensure_ascii=False)}]
    msgs.append({"role": "user", "content": card_text})
    return msgs

为什么 few-shot 能补上这 21 个百分点

我逐条看了裸 prompt 漏抽的样本，发现模型不是不认识参数，而是不知道粒度——「扭矩 45±5 N·m」它只抽「扭矩」，「首件检验 3 件」它整个丢掉。few-shot 样例真正教给模型的是什么叫一个参数：连数值、公差、单位一起保留，检验类步骤也算关键参数。这种隐性规则用文字解释很啰嗦，三个例子一次说清。这也是我认为微调不划算的深层原因：我们要迁移的不是领域知识，是输出粒度偏好。

踩过的坑

坑一：样例里出现真实零件号，模型照抄。第一版样例我直接从生产数据里摘，带着 X374X 这样的真实编号，结果有的输出把样例里的编号写进了新工单，改成全部脱敏（PART-A 之类）后才干净。坑二：样例顺序有偏差。我发现把「钣金」样例放在最前，模型对注塑卡也倾向于输出钣金的参数格式，解决办法是按零件类型动态选样例、每次固定 3 个同类样例。坑三：样例太多反而变差。我试过塞 12 个样例，完整率从 92% 掉到 86%——示例把上下文吃掉了，真正的工艺卡被挤到后面。三个样例是甜点，再多就是噪声。

什么时候我会真的去微调

这次没微调，不代表微调没用。我给自己定了三条触发线：一是任务依赖大量专属知识，few-shot 塞不下，比如要把整套企业标准内化；二是调用量极大且延迟敏感，小模型微调后本地部署的单次成本是大模型调用的三十分之一，量起来能回本——按我们的量算每天 200 次调用，微调用三年都回不了本；三是输出风格高度固定，few-shot 压不住。三条都不满足，就老老实实写 prompt。

结论

把这次的结论写成一句话：先穷尽 prompt、schema 和 few-shot，再考虑微调。微调解决的是「模型不知道」，而更多时候模型是「知道但没按你要的粒度输出」。那 2 个百分点的差距不值得 10 小时标注——但如果哪天日调用量涨两个数量级，或者要把整套国标内化进模型，我会毫不犹豫地回去做微调。取舍不是「微调高级、prompt 低级」，而是看你的问题到底卡在知识还是卡在表达。
