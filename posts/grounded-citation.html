让 RAG 回答逐句带出处：我把幻觉率从 18% 压到 3%

2026年11月19日·约 10 分钟#AI#幻觉抑制#实践

上周差点酿成事故：同事在 NPI 系统里问「某零件的拧紧扭矩标准是多少」，助手答得头头是道，还标注「来自工艺规范文档」。他照着写进了工艺卡——那是另一个机型的参数。模型没瞎编，那段数字确实躺在我的知识库里，只是被安错了出处。这次之后，我给 RAG 加了一道「引用溯源」闸门：每个句子必须绑定一段真实原文，找不到出处就宁可说不知道。

为什么「来自 XX 文档」这句话不可信

我最初的做法是让模型在答案末尾附上来源，比如「以上来自《工艺规范 v3》第 12 页」。听着靠谱，但我抽查了 50 条回答，发现 9 条的出处是模型编的——文档名对、页码却是瞎写的，或者数字来自 A 段却被说成 B 段。让模型自己报告出处，等于让它给自己的答案盖章，本质上还是幻觉。溯源必须由程序来判，不能交给生成环节。

改成「逐句锚定」，让程序来判出处

新流程分两步：先检索候选片段，让模型只依据片段作答、并给每句标上所用片段编号；再由程序把答案拆成句子，逐句和候选片段做自然语言推理（NLI）判断蕴含关系，取最高分作为该句出处。只有分数过阈值的句子才保留出处标记。

def grounded_answer(question, hits, llm, nli, min_score=0.82):
    lines = []
    for i, (text, doc_id, page) in enumerate(hits):
        lines.append("[" + str(i) + "] " + text)
    ctx = chr(10).join(lines)
    draft = llm("只依据片段回答，逐句标注编号：" + ctx + " 问：" + question)
    cited = []
    for s in split_sentences(draft):
        best = max(hits, key=lambda h: nli.entailment(s, h[0]))
        score, doc_id, page = best[0], best[1], best[2]
        cited.append({"text": s, "source": doc_id if score >= min_score else None,
                      "page": page, "score": round(score, 2)})
    dropped = [c for c in cited if c["source"] is None]
    verdict = "partial" if dropped else "ok"
    return {"answer": cited, "verdict": verdict, "dropped": len(dropped)}

阈值 0.82 是怎么试出来的

我拿 60 条有标准答案的工艺问题做评测。阈值 0.70 时，出处正确率只有 76%——模型把相似但不同的机型参数也判成了出处。提到 0.82，出处正确率升到 94%，但 12% 的句子因为找不到足够匹配的片段被标成「无出处」。再往上到 0.90，正确率几乎不涨，「无出处」却涨到 21%，答案变得支离破碎。0.82 是准确率与可用性的平衡点。

踩坑：无出处的句子怎么处理

第一版我把无出处的句子直接删掉，结果答案经常读不通——被删的恰恰是承上启下的连接句。改成保留句子、但打上「【未找到依据】」标记并在前端高亮，让用户自己判断。另外发现 NLI 模型对数字极不敏感：「扭矩 45N·m」和「扭矩 54N·m」的蕴含分数几乎一样。我补了一条硬规则——答案里的数字必须能在绑定片段里原样找到，否则强制标无出处。就这一条，把数字类幻觉又砍掉一半。

结论

上线一个月，抽查幻觉率从 18% 降到 3%，代价是约 12% 的句子被标为无出处、需要人工复核。引用溯源的本质不是让模型更诚实，而是把「这句话有没有依据」从模型的自由裁量，变成程序可验证的判断。模型负责生成，程序负责举证——分工清楚了，幻觉才压得住。同一套思路也能搬到工作日报系统里自动生成的周报：凡是涉及数字和结论，都得能指回原始记录。
