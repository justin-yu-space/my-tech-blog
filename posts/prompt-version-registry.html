把 Prompt 从代码里搬出来后，我第一次能回答「上周那批摘要到底是谁生成的」

NPI 系统里有个功能：读工艺卡文本，生成结构化的工序摘要，给项目概览页用。上线两个月相安无事，直到某天有人问「为什么这周的摘要都变得特别短，关键参数都没了」。我去翻代码，发现三天前我自己为了「让输出更简洁」，在 prompt 末尾加了一句「请简洁一点」。改的时候觉得无所谓，出问题时才发现：这个 prompt 是硬编码在 Python 里的一个三行字符串，没有版本号、没有变更记录、也没法只对一部分请求回滚。那次之后我把它搬进了版本注册表。

事故现场：一句「请简洁一点」，200 份摘要全变样

那句「请简洁一点」的杀伤力超出预期。模型把「简洁」理解成「删掉所有列举项」，结果 key_params 字段从平均 4.2 项变成 0.8 项，risks 有一半直接返回空数组。更尴尬的是排查过程：我知道输出变了，但不知道从哪天开始变、影响了多少条、改之前长什么样——因为旧 prompt 已经被覆盖，只在 git 里留了一个 diff，而生产环境的调用参数（模型、temperature）压根没记录。

拆出来：一个 prompt 一个文件，版本号写在文件名里

我把所有 prompt 挪到 prompts/ 目录，命名规则是 {id}.v{n}.md，文件头用 front-matter 记元信息，正文是模板。这样「当前用哪版」变成一个显式的配置项，而不是散落在代码里的字符串。

# prompts/summary_card.v3.md
---
id: summary_card
version: 3
model: qwen-plus
temperature: 0.2
updated: 2026-11-21
note: 补回 key_params 列举要求，禁止模型自行省略
---
你是工艺工程师助手。请阅读下面的工艺卡文本，输出 JSON：
{"process": "...", "key_params": ["..."], "risks": ["..."]}

要求：key_params 至少列出 3 项，若原文没有明确参数则填 ["未标注"]，
不允许返回空数组。只输出 JSON，不要任何解释。

# registry.py
import hashlib, yaml

def load(prompt_id, version):
    path = "prompts/" + prompt_id + ".v" + str(version) + ".md"
    raw = open(path, encoding="utf-8").read()
    head, body = raw.split("---", 2)[1:]
    meta = yaml.safe_load(head)
    meta["sha8"] = hashlib.sha256(body.encode()).hexdigest()[:8]
    meta["body"] = body.strip()
    return meta

三件事必须落到库里：prompt 版本、模型、参数

光有文件不够，关键是调用时把「这次用了什么」写进业务库。我在 audit_log 里加了三个字段：prompt_id、prompt_version、prompt_sha8，再带上 model 和 temperature。这一步做起来只有十几行代码，但它让「上周那批摘要谁生成的」从不可回答变成了一个 SQL 查询。我甚至不用查 git——直接按 sha8 分组，就能看出哪一批输出是同一次生成逻辑的产物。

坑一：缓存 key 里没带版本号，回滚后命中的还是坏结果

发现摘要变短后我立刻把版本从 v3 回滚到 v2，重启服务，重新生成——结果输出还是短的。原因是我之前给摘要做了结果缓存，key 是「文件哈希 + 模型名」，没有 prompt 版本。于是所有请求都精准命中了三天前缓存下来的坏结果。Prompt 版本必须进缓存 key，它是生成逻辑的一部分，跟模型名同级。改成 hash(file) + model + prompt_sha8 之后，回滚立刻生效，旧缓存自然失效，不需要手动清。

坑二：灰度 10% 看不出差异，因为没有对照组

后来我想做灰度：v4 只放 10% 的流量，稳定了再全量。第一轮跑了一周，我觉得「看起来没什么区别」，准备全量。回头一算才发现我根本没设对照组——那 10% 的请求量只有 40 条左右，而摘要长度的自然波动就有 ±30%，40 条样本的均值差异完全淹没在噪声里。真正让我判断出差异的，是按 prompt_version 分组比对同一批文件：拿 30 份文件分别用 v3 和 v4 各跑一次，逐字段对比，才看出 v4 在 risks 上更容易漏项。灰度不是发出去看天，是要有能算出差别的样本量。

坑三：模板变量漂移，模型自己把缺失的字段编了出来

注册表化之后模板里开始有占位变量，比如 {part_no}、{process_text}。有次上游传了空字符串，模板变成「零件号：，工艺内容：xxx」，模型没有报错，而是自己补了一个看起来合理的零件号。变量缺失必须在渲染前拦截，不能指望模型发现。我在 render() 里加了必填校验，缺任何一个直接抛异常并记录到日志，宁可这条摘要生成失败，也不要一条编造了零件号的摘要流到概览页上。

结论

现在我的习惯是：任何要进生产的 prompt，第一件事不是调措辞，而是给它一个版本号和一条记录。听起来像流程负担，实际上它把三类问题一次解决了——出事能定位到具体版本、回滚是一个数字的事、效果对比有分组依据。Prompt 长得像代码里的字符串，但它的生命周期更像配置：会被改、会被回滚、需要灰度、必须留痕。当成字符串管理，就只能靠记忆和运气。
