我给 AI 检索建了套 60 题评测集，才发现「优化见效」全是自我感觉

上周我在 file-manager 的智能文件问答里改了一版检索策略，跑完评测我跟同事说「召回率从 72% 提到 89%」。他问了一句「你怎么测的」，我愣住了——我确实只有一组随手挑的 20 个问题，而且答案是我自己让模型生成的。那一刻我意识到，我过去说的很多「优化见效」，可能只是自我感觉。于是我花了三天，认真建了一套评测集。

第一版评测集：我给自己挖的坑

最开始我的「评测」特别随意：想到几个问题就手动问一问，觉得答得不错就算通过。这种方式有三个致命问题：样本太少（20 题，一题就占 5%，改一个字都可能让数字跳好几个点）、全是我脑子里记得的答案（天然偏向当前实现）、而且没有标准答案，全靠我肉眼判断。更要命的是，我一度让模型自己生成「标准答案」——用当前系统跑一遍，把输出存下来当 gold。这等于让学生出题自己考自己，怎么改都是高分。

评测集怎么来：真实 query 优先，合成只做补充

我定了三条规矩。第一，优先从真实日志里挖 query：file-manager 上线半年积累的搜索框输入，脱敏后挑出 60 条，按意图分层——文件名查找 20 条、内容检索 20 条、跨目录统计 20 条。第二，标准答案必须人工标注，且标注时看不到当前系统的输出（避免被带偏）。第三，train/test 分离：40 题用来调参，20 题全程封存，只在最终验收时打开一次。评测集一旦参与调参就被污染了，再拿来证明效果等于既当裁判又当运动员。

指标不只看准确率：我加了 recall@5 和 MRR

文件检索是「相关文件有没有被召回到前 5」的问题，用整体准确率衡量太粗糙。我改用两个信息检索指标：recall@5（前 5 条里命中正确文件的比例）和 MRR（正确文件排名倒数的均值，衡量排序质量）。

import json

def evaluate(results_by_query, gold_by_query, ks=(1, 5)):
    """results: query -> [file_id, ...]；gold: query -> set(file_id)"""
    out = {"recall": {}, "mrr": 0.0}
    n = len(gold_by_query)
    for k in ks:
        hit = 0
        for q, gold in gold_by_query.items():
            topk = set(results_by_query[q][:k])
            if topk & gold:
                hit += 1
        out["recall"]["@" + str(k)] = round(hit / n, 3)
    rr = 0.0
    for q, gold in gold_by_query.items():
        for rank, fid in enumerate(results_by_query[q], start=1):
            if fid in gold:
                rr += 1.0 / rank
                break
    out["mrr"] = round(rr / n, 3)
    return out

gold = json.load(open("gold.json"))
pred = json.load(open("pred_v3.json"))
print(evaluate(pred, gold))

数字的真相：三次「优化」有两次是波动

有了固定评测集，我把过去三个所谓「优化版本」重新跑了一遍，结果很打脸：v1 到 v2 的 recall@5 从 72% 到 74%，在 40 题上只是 ±1 题的波动，根本不算提升；v2 到 v3 从 74% 到 81%，这次是真涨——原因是把文件类型和路径一起做了混合检索。之前我凭肉眼觉得「v1→v2 明显好了」，其实是确认偏误。没有固定评测集，你连自己有没有进步都不知道。

踩坑：过拟合评测集与只测 happy path

两个坑值得记。一是过拟合：我盯着 train 40 题反复调，把参数调到 95%，一开 test 20 题就掉到 83%——典型的过拟合，所以我给自己立规矩，test 集一个月只开一次。二是评测集只有「正常问题」，漏了边界：空查询、只有两个字的查询、包含特殊字符的文件名。补了 8 条 bad case 后才发现，系统对空查询会返回随机文件——这种问题在 happy path 评测里永远发现不了。

结论

现在每次改检索逻辑，我都先跑一遍 40 题的 train 集看有没有回退，验收时才开 test 集。评测集不是一次性的作业，而是跟着系统一起长大的资产：它把「我觉得」变成「数字说」，还顺便给每次改动装了刹车。这件事最大的收获其实不是那个 89%，而是我终于能诚实地区分「真的变好了」和「我以为变好了」。
